# 仓库品类分析决策工具：项目概述

**项目状态**：开发前架构已确定，进入 M0 契约、数据库、模块边界和 UI 基线冻结阶段  
**产品形态**：本地 Windows 工作台 + 商户 Web 管理端 + 开发者管理模式 + 微信小程序预留接口  
**适用对象**：中小仓库管理者、商家、采购负责人和运营分析人员

> 本概述是面向客户、销售、支持和新成员的独立说明。接口、数据库、模块依赖和开发验收以 `仓库品类分析决策工具-开发规划与协作需求文档.md` V2.0 及 A/B 个人需求文档为准。

---

## 1. 这个项目是什么

仓库品类分析决策工具是一套帮助商户管理库存、识别动销和积压、辅助补货以及自动执行分析任务的工作台。

它采用“本地优先”设计：商户的货品、库存流水、成本、采购和分析明细主要保存在商户自己的电脑上；开发者平台不默认保存完整库存业务数据，只负责账号、许可证、配置、版本、设备状态、任务状态和技术日志。

项目不是为每个商户单独开发一套程序。商户在官网注册账号、下载相应行业类型的安装包，登录后即可使用同一套产品能力。未来可以通过产品类型和配置支持零售、批发、制造、汽配等不同场景。

---

## 2. 能解决什么问题

### 数据有但不会用

把 Excel、CSV 或其他系统导出的流水导入工作台，统一清洗、校验并生成可对比的指标。

### 采购依靠经验

通过出货率、周转率、库龄、ABC 分类、安全库存和补货点，帮助商户发现哪些品类应该补货、哪些库存需要处理。

### 结果无法持续触达

工作台可以按计划执行分析并生成报告；云端 Web 端可以查看任务是否执行、工作台是否在线以及是否存在同步或运行故障。

### 数据隐私和网络不稳定

核心业务数据留在本地，断网时仍可查看、导入、分析、生成报告和备份；恢复网络后再同步账号状态、配置、任务状态和必要的技术日志。

## 3. 谁使用它

| 使用者 | 主要用途 |
|---|---|
| 仓库管理者 | 查看库存、库龄、动销、呆滞和异常，安排盘点和处理 |
| 商家或采购负责人 | 查看补货建议、周转情况和品类对比，辅助采购决策 |
| 运营或分析人员 | 导入数据、运行分析、导出报告和进行周期复盘 |
| 开发者和技术支持 | 管理商户授权、版本、配置、Skill、模型、设备状态和技术日志 |

第一版只提供一个商户主账号，不开发员工邀请和复杂组织权限。底层保留商户、账号和设备标识，方便后续扩展。

## 4. 产品由哪些部分组成

### 官网和下载中心

- 产品介绍和适用行业。
- Windows 安装包下载。
- 版本说明、校验值和更新日志。
- 首次安装、登录、数据导入、备份、恢复和同步教程。
- 隐私说明、常见问题和客户支持入口。

### 本地工作台

- 登录、设备注册和授权检查。
- 货品、条码、仓库、库位、批次和供应商维护。
- CSV/Excel 导入、字段映射、错误隔离和修复。
- 出入库、盘点、调拨、报废和冲销事件管理。
- KPI、ABC、库龄、呆滞、补货和预测分析。
- 调度任务、报告导出、备份和恢复。
- 托盘常驻、配置同步、状态上报和小程序事件同步。

### 商户 Web 管理端

- 商户账号和许可证状态。
- 工作台设备、版本、在线状态和最后同步时间。
- 小程序绑定关系。
- 任务执行状态、失败原因和待同步数量。
- 商户允许修改的配置和通知设置。

### 开发者管理模式

- 商户、产品类型、许可证和设备管理。
- 全局/商户配置、Skill、模型和 API 配额管理。
- 安装包、版本、灰度发布和升级策略管理。
- 心跳、同步、任务和技术日志查看。
- 临时技术支持授权、审计和诊断包管理。

### 微信小程序预留端

本期不开发小程序页面，只保留接口和 Mock 验证。未来用于扫码入库、出库、盘点、调拨和采购录入。小程序提交库存事件，工作台负责本地校验和写入，不允许小程序直接操作本地数据库。

## 5. 用户如何使用

1. 商户在官网下载对应行业类型的工作台安装包。
2. 安装后注册或登录商户账号。
3. 工作台注册本机设备并获取许可证和产品配置。
4. 商户导入货品和历史库存流水。
5. 工作台在本地保存业务数据并执行分析。
6. 商户在 Web 端查看工作台在线状态、任务状态和同步状态。
7. 未来通过小程序绑定工作台，扫码提交库存事件。
8. 工作台联网后拉取事件，在本地校验并写入库存事件表。
9. 商户可导出报告、业务数据和加密备份。
10. 软件升级前自动备份，升级失败时恢复旧版本或备份。

## 6. 数据存在哪里

### 商户本地保存

- SKU、条码、货品分类和单位。
- 库存事件、库存余额、库存快照。
- 成本、采购价格、供应商、批次和库位。
- 分析结果、预警、报告和完整业务审计日志。
- 本地配置、导入记录和备份记录。

### 开发者平台保存

- 商户账号、设备、许可证和产品类型。
- 配置版本、Skill 版本、模型引用和功能开关。
- 工作台心跳、客户端版本、任务状态和同步状态。
- 脱敏技术日志、错误码、耗时和审计记录。
- 小程序事件的短期加密同步信封和处理状态。

开发者平台默认不保存商户完整 SKU、库存数量、成本、采购价格、供应商和完整业务报告。小程序事件如果必须经过云端，仅以加密信封短期中继，工作台确认后按策略删除原始密文。

## 7. 项目技术架构

```text
官网 / 商户 Web / 开发者 Web
              |
        FastAPI 控制平面
              |
      PostgreSQL 控制数据库
              |
     HTTPS + SSE + 临时加密中继
              |
工作台托盘 Agent + PySide6 工作台
              |
       SQLite 本地业务数据库
              |
      Python Warehouse Engine
```

### 技术选型

- 本地工作台：Python 3.11、PySide6、SQLite、SQLAlchemy 2、Alembic、pandas、numpy、scipy、statsmodels。
- 云端控制平面：FastAPI、Pydantic 2、PostgreSQL、Docker Compose、Caddy HTTPS。
- Web：Next.js App Router、React、TypeScript、Ant Design、TanStack Query、MDX。
- 实时状态：SSE，断线自动重连，轮询降级。
- 打包发布：PyInstaller `--onedir`、Inno Setup/NSIS、Windows 代码签名。
- 测试：pytest、pytest-qt、Hypothesis、Playwright、契约测试和性能基准。

第一版不引入 Redis、消息队列和多主工作台，先保证两人能维护、客户能安装和本地业务闭环稳定。

### 前后端和模块连接

- Web 前端只通过 FastAPI `/api/v1` 和生成的 OpenAPI client 访问云端，不直连数据库。
- 桌面 UI 通过本地 Application Service 访问 SQLite 和引擎，托盘 Agent 负责后台心跳、任务、配置和同步。
- FastAPI 只管理账号、许可证、设备、配置、任务、临时加密信封和脱敏技术日志；不保存完整库存业务明细。
- 前端、API、本地服务和引擎按模块隔离，使用版本化 contracts、FakeEngine 和自动化契约测试衔接。

### 第一版 UI 风格

- 工作台采用仓库运营控制台风格：克制、清晰、可扫描，优先表格、筛选、状态和错误定位。
- 使用深蓝导航、青绿成功、琥珀警告、红色错误和浅灰背景；圆角不超过 6px，不使用大面积渐变或装饰性卡片。
- 首屏持续显示网络、授权、待同步和任务状态；异步操作必须有加载、成功、失败和重试反馈。
- 复杂导入和分析以桌面端为主，移动 Web 只保证账号、设备、任务和绑定管理。

## 8. 数据库架构

项目有两套正式数据库：

### 本地业务数据库：SQLite

每个商户主工作台一个本地数据库，保存完整业务数据。主要表包括：

- `sku`、`barcode`、`warehouse`、`location`、`supplier`、`supplier_sku`、`lot`。
- `inventory_event`、`inventory_event_line`、`inventory_balance`、`stock_snapshot`。
- `purchase_order`、`purchase_order_line`。
- `import_batch`、`import_error`、`analysis_run`、`analysis_result`、`report_artifact`。
- `local_audit_log`、`backup_record`、`sync_inbox`、`sync_outbox`、`sync_checkpoint`、`config_cache`。

`inventory_event` 是库存事实来源，余额是可重建投影。错误不直接覆盖库存，而是使用冲销或调整事件。

### 云端控制数据库：PostgreSQL

开发者平台一个控制数据库，保存控制面数据。主要表包括：

- `tenant`、`account`、`session`、`device`、`mini_binding`。
- `product_profile`、`license`、`feature_grant`。
- `config_version`、`skill_release`、`model_provider`、`release`。
- `task`、`task_run`、`heartbeat`、`sync_envelope`。
- `telemetry_event`、`audit_log`。

云端控制库不建立商户完整 `sku`、`movement` 和 `unit_cost` 表。

## 11. 客户可以获得什么

- 无需安装 Python 或数据库，下载安装包即可使用。
- 原始库存和成本数据主要留在客户自己的电脑。
- 导入数据时能定位具体错误，不需要手工猜问题。
- 分析结果可以回答动销、积压、周转和补货问题。
- 网络中断时本地核心工作不中断。
- Web 端能看到工作台是否在线、任务是否成功和是否有同步积压。
- 重要数据可以备份、导出、恢复和迁移到另一台电脑。
- 软件升级有版本说明、签名、备份和回滚方案。
- 技术支持通过脱敏诊断信息排查问题，不默认读取完整业务明细。

## 12. 当前限制和后续方向

- 第一版只有一个商户主账号，不含员工权限体系。
- 第一版只支持一个主工作台，多工作台多主同步后续再做。
- 工作台关机时，小程序事件只能进入待同步状态，不能立即写入本地数据库。
- 开发者平台短暂不可用时，工作台依赖缓存配置和离线宽限期。
- 小程序页面、微信审核和正式发布不在当前开发范围。
- 后续可增加员工、多仓库、多工作台、本地模型、云端加密备份和完整微信扫码流程。

**项目核心原则：云端统一管理产品能力和运行状态，本地保存并处理商户业务数据；先确保数据正确、可追溯、可恢复，再逐步增加 AI 和移动端能力。**
